## Походження і правила статусів

Під час Stage 9 початкове академічне ТЗ було недоступне, тому таблиця нижче фіксує **поточний функціональний обсяг та репозиторні бізнес-правила**. У Stage 10 оператор надав [оригінальні джерела](../requirements/Stage10_Requirements_Source_Bundle.md); повне зіставлення stories із backend, frontend, AI та доказами додано в [requirements-coverage](../stage10/requirements-coverage.md), а облік усіх 90 API routes і 35 Vue Router records — у [api-ui-coverage](../stage10/api-ui-coverage.md). Виявлено формальні прогалини: зміна/відновлення пароля, AI-зміни занять/замін, загальний відсоток виконання й навантаження за предметами. Таблиця Stage 9 не є заявою про повну відповідність оригінальним вимогам.

Наявне джерело внутрішніх правил — [business-rules.md](https://github.com/BashukOleksii/Student-AI-Planner-Backend/blob/f618bba290f919dc3561b0462c59b3b86ade82d8/docs/business-rules.md). Його BR-позначення вже існують у репозиторії. Рішення щодо фактичної реалізації звірено з поточним кодом, бо деякі вступні тексти старих документів описують попередні етапи.

| Статус                | Значення                                                                                |
| --------------------- | --------------------------------------------------------------------------------------- |
| IMPLEMENTED           | Поточний код реалізує зазначений обсяг; рівень перевірки подано окремо                  |
| PARTIALLY IMPLEMENTED | Реалізовано лише прямо названу частину ширшого сценарію                                 |
| NOT IMPLEMENTED       | Відповідної робочої можливості у поточних маршрутах/коді немає                          |
| NOT VERIFIED          | Потрібного зовнішнього/операційного доказу немає; це не твердження про відсутність коду |

`PASS`, `BLOCKED`, `NOT RUN` у стовпці доказів стосуються виконання тестів. Наявність функції не перетворює пропущений тест на PASS.

## Що потрібно узгодити з кафедрою

Оригінальне ТЗ вже отримано й зіставлено у Stage 10. Потрібно узгодити зафіксовані там неоднозначності (скасування/видалення нагадувань, автономність перенесення, AI-керування вільним часом, формат звіту) та окремо схвалити нові архітектурні можливості. S1/S2 не вимагають явно email/SMS, календарного експорту чи downloadable report; кандидатні інтеграції S3 не стали автоматично обов'язковими. Figma/provider/delivery operational gates залишаються окремими. Не називати цей проєкт експериментом із доведеним підвищенням навчальної продуктивності: відповідного дослідження не проводилось.
