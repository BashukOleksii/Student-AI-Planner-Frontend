# Оновлення `/planning/replanning`

Зміни зроблено в локальному Frontend на `main`. До редагування прочитано `AGENTS.md`, перевірено `git status --short` — робоче дерево було чистим.

## Контракт і межі

Корінь сусіднього Backend підтверджено командою `git -C ../student-planner-backend rev-parse --show-toplevel`. Прочитано контролер перепланування, запити періоду, сервіси огляду/підтвердження та ресурси відповіді. Backend не змінювався.

Чинний `POST /api/planning/replanning/preview` приймає період без ID сесії. З `task_id: null` та `subtask_id: null` сервер перевіряє всі заплановані сесії, що перетинають вибраний період. Обхідних запитів для кожної сесії немає. Огляд не зберігає план. Підтвердження використовує чинний токен і наявні прапорці згоди, без нового API.

**Обмеження відповіді підтвердження:** вона не повертає початковий період огляду, часовий пояс, старі інтервали й причини. Тому після збереження UI показує явно підписані «Дати доданих сесій», обчислені з фактичних `replacement_sessions` у часовому поясі профілю. Це діапазон створених сесій, а не початковий період огляду. Поля форми й попередній огляд не підставляються як збережені дані. Якщо нових сесій немає, діапазон не вигадується. Для відображення саме початкового періоду після підтвердження потрібні відповідні поля у серверній відповіді; у цьому етапі контракт не змінювався.

Зв'язки між початковими та створеними сесіями беруться з уже наявного `replacement_groups`. Старі відповіді без цих зв'язків показують створені сесії окремим списком, без припущень про відповідність. Нерозміщений залишок береться зі збереженого `summary.untransferred_seconds` і показується окремо.

## Поведінка

- Початкова картка містить тільки дати та «Перевірити план». Підстановка дат із посилання не запускає запит. Валідація періоду 1–31 день збережена.
- Огляд розділено на картки підсумку, змін, унікальних попереджень та дій. До підтвердження видно «Ще не збережено» й фактичний період відповіді.
- Один запис описує початкову сесію: роботу, старий час, причину, всі нові проміжки та залишок без часу. Повторні причини прибрано з попереджень; інші збережено.
- Пагінація показує до п'яти початкових сесій; попередження та великі збережені списки також мають сторінки по п'ять записів. Вона змінює лише відображення. Підтверджується вся пропозиція.
- Згоди на поділ, частковий результат і скасування без заміни залишаються поза списком. Відхилення не виконує записів. Чинна обробка прострочення, застарілих даних та невизначеного результату підтвердження збережена.
- «Нічого переносити не потрібно» відрізняється від «Проблеми є, але нового часу не знайдено». Для чистого періоду немає порожніх карток або кнопки підтвердження.
- Після успішного підтвердження показано «Зміни збережено», фактично додані сесії, скасування та окремий залишок. Є перехід до «Навчальних сесій».

## Ізоляція спільних компонентів

Маршрути огляду плану, відновлення та перепланування використовують `PlanPreviewView.vue`. `PlanningReview.vue` і `StudyProposal.vue` також використовуються автоматичними пропозиціями та AI. Їх не змінено: перепланування отримало окремий `ReplanningReport.vue` зі scoped-стилями. `RecoveryPlanReview.vue` та ручне перенесення у `StudySessionView.vue` не змінено. Новий параметр `periodOnly` у `usePlanningScope` за замовчуванням вимкнено.

## Змінені файли

Реалізація:

- `src/views/PlanPreviewView.vue` — компактна форма, підключення нового огляду та наявних дій.
- `src/components/planning/ReplanningReport.vue` — картки огляду/результату, групування, пагінація та адаптивність.
- `src/utils/replanningPresentation.ts` — короткі причини, відокремлення проблемних сесій і усунення повторних попереджень.
- `src/composables/usePlanningScope.ts` — режим періоду без непотрібного завантаження вибору роботи.
- `src/types/planning.ts` — тип уже наявного поля `replacement_groups`.

Перевірки та звіт:

- `tests/replanning-page.test.ts` — запит без ID, підстановка/валідація дат, порожній результат, відсутність заміни, ручні рішення, поділ, повторні причини, підтвердження зі сторінки 2, помилки та збережені дані.
- `tests/helpers/planningBackend.ts` — відповідність мок-відповіді чинному `replacement_groups`.
- `tests/planning.test.ts` — актуальні підписи й очікування огляду перепланування.
- `e2e/replanning-page.spec.ts` — браузерні сценарії desktop/mobile.
- `e2e/planning.spec.ts` — оновлені два підписи перепланування в наявному сценарії.
- `docs/replanning-page-ui.md` — цей звіт.
