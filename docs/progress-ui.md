# Компактна сторінка прогресу

Зміни виконано лише в локальному Frontend, у `main`. На початку перевірено корінь репозиторію, `git status --short` був порожній, прочитано `AGENTS.md`. Backend, AI, API-контракти й розрахунки не змінено.

## Що змінено

`/statistics` показує одну сторінку з чотирма секціями:

1. **Огляд прогресу** — шість компактних карток: час у плані, записаний фактичний час, завершені/пропущені сесії, завершені завдання й підзавдання за період.
2. **Статистика за предметами** — кільцева діаграма, короткі рядки з часом, кількістю сесій і часткою навчального часу. Невідомий фактичний час позначено «—». Збережено порядок API; «Без предмета» названо «Без прив’язки до предмета». Для понад п’яти предметів є пагінація по п’ять; діаграма охоплює весь набір, а новий період повертає список на першу сторінку.
3. **Тренди** — чотири картки зі стовпчиками: записані хвилини, завершені сесії, пропущені сесії, завершені завдання за днями. Нульові дні й порядок дат збережено. Довгі періоди прокручуються всередині графіка, не розширюючи сторінку.
4. **Порівняння періодів** — шість карток із A, B, різницею API, нейтральною стрілкою та двома смугами. Зростання пропусків не позначається покращенням. Дати результату беруться з відповіді, а не незастосованих полів форми.

Прибрано дві верхні кнопки «Останні сім днів» / «Поточний тиждень», навігацію між звітами, розгорнутий блок «Поточний стан роботи — за весь час», дублюючі таблиці та секції «Докладніше». Скриншоти в повідомленні не були прикріплені; як другорядний блок прибрано саме розгорнутий стан за весь час, відокремлений від обраного періоду. Загальний відсоток завершення за весь час не видається за прогрес періоду.

Старі адреси `/statistics/trends` і `/statistics/comparison` залишаються доступними та відкривають ту саму сторінку. Нових вкладок або навігаційних кнопок для них немає.

## Графіки й дані

Перевикористано й розширено наявний **`MetricChart.vue`**: горизонтальні смуги, денні стовпчики та SVG donut. Нових залежностей немає. Кольори беруться з чинних semantic tokens для світлої й темної тем. Числа доступні як текст, діаграма має опис, денні значення доступні з клавіатури; дублюючі приховані таблиці не потрібні.

Кільце й смуги відображають лише пропорції наявних `scheduled_seconds`, без нового показника успішності. Предметне навантаження включає заплановані та завершені сесії; верхня картка «У плані» показує лише чинні planned-сесії, тому ці суми можуть відрізнятися. Невідомі фактичні хвилини не замінюються запланованими або нулем. Коротке позначення неповних даних збережено в огляді, предметах, трендах і порівнянні.

Завантаження використовує чинні `statisticsApi` та `useResource` окремо для трьох звітів. Зміна головного періоду оновлює огляд і тренди. Порівняння має незалежні періоди A/B й явне застосування. Помилка одного запиту не приховує інші секції; повторення робить лише відповідний GET. Чинні правила 1–31 день, однакова довжина та неперетинання порівнюваних періодів збережено.

## Змінені файли

- `src/views/StatisticsView.vue` — спільна сторінка, незалежне завантаження трьох звітів і форми.
- `src/views/ComparisonView.vue` — сумісний вхід зі старої адреси до спільної сторінки.
- `src/components/statistics/ReportRangeForm.vue` — компактна форма без пресетів та зайвих підписів.
- `src/components/statistics/MetricChart.vue` — повторно використаний chart-компонент із новими варіантами.
- `src/components/statistics/SubjectWorkload.vue` — кільце, компактні предмети та пагінація.
- `src/components/statistics/ProgressOverview.vue`, `ProgressTrends.vue`, `PeriodComparison.vue` — предметні компоненти відображення, без API-викликів.
- `src/utils/statistics.ts` — спільна палітра графіків; чинна валідація не змінена.
- `tests/activity.test.ts`, `tests/statistics-charts.test.ts` — регресії представлення, контракту та взаємодії.
- `e2e/activity.spec.ts` — браузерні сценарії спільної сторінки, періодів, порожніх даних, пагінації, помилок і тем.
- `docs/progress-ui.md` — цей звіт.

## Перевірки

Точні команди з кореня Frontend:

```bash
npm run type-check
npm run build
npx vitest run tests/activity.test.ts tests/statistics-charts.test.ts tests/page-content.test.ts
npx playwright test e2e/activity.spec.ts e2e/page-content.spec.ts --grep 'progress|statistics' --workers=4
```

- Type checking — успішно, exit 0.
- Production build — успішно, exit 0.
- Vitest — **97/97 тестів, 3 файли**, exit 0.
- Playwright — **20/20 сценаріїв**, desktop/mobile Chromium, exit 0 (37,5 с). Початковий запуск із `--workers=2` також показав 20 успішних сценаріїв, але процес завершився SIGTERM; наведений повторний запуск із чотирма workers завершився коректно.
- Prettier для всіх змінених файлів і `git diff --check` — успішно.

Браузерні перевірки використовують підробний API, desktop/mobile Chromium, світлу/темну теми та ширини 320, 390, 768, 1024, 1440 px. Існуючі content-сценарії також перевіряють доступність через axe, loading/server-error/empty та старі адреси.

Живий Backend, Firefox/Safari та повний набір тестів застосунку не перевірялися. Окремим етапом можна додати вибір серій для трендів або детальніший огляд одного предмета; цього завдання вони не потребують.
