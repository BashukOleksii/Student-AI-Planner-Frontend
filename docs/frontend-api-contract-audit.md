## Changes and findings

- Recovery had compile-time types without runtime checks on the fields enabling
  confirmation. Invalid responses now fail with the safe 502 error boundary.
- Recovery confirmation/rejection identity is checked; refresh intentionally permits
  a different UUID. Unknown consent fields remain readable and block confirmation.
- Historical teacherless semester **before** rows are permitted; proposed rewritten
  rows continue to require the server's current subject/teacher constraints.
- No supported global task sorting parameter, session `task_id` query, task remaining
  effort field, or import-history collection endpoint was found. The UI does not
  invent any of them. Remaining effort is shown where planning returns it, not
  reconstructed from estimates/completion on task cards. Saved import IDs and
  existing receipts/deep links remain the available import-history access.
- No other path/method/envelope mismatch was found in the inspected clients.
  Authorization, recurrence, parity, allocation, conflict detection, status policy,
  scheduler operation and final write validity remain Laravel responsibilities.

## Verification boundary

Offline HTTP mocks and browser tests exercise these interfaces. They do not establish
that a production database, scheduler or provider is running with the audited source.
No Backend code, database migration, production write or paid LLM test was executed.
