## Джерело та правила оцінки

Прочитано всі три джерела [Stage10_Requirements_Source_Bundle.md](../requirements/Stage10_Requirements_Source_Bundle.md). Операторський файл спочатку надано в корені репозиторію; копію у запитаному `docs/requirements/` збережено без редагування. Посилання `S1:L12` та `S2:L26–34` — номер джерела та **рядки оригінальної копії**, до форматування Markdown. Орфографію джерела не виправлено. Нижче згруповано всі змістовні user stories S2; дубльовані формулювання включено до тих самих груп. R01–R48 — локальні ID аудиту, не номери першоджерела.

За явною інструкцією Stage 10 первинні джерела — S1 (постановка) та S2 (детальні stories). S3 — напрям розвитку; приклади зовнішніх інтеграцій не стали автоматично обов'язковими. Код визначає наявність реалізації, джерело — бажану поведінку. `IMPLEMENTED` не означає, що зовнішня операція виконувалася у Stage 10. `PARTIALLY IMPLEMENTED` зберігає відсутню частину. `NOT VERIFIED` не підміняє відсутню реалізацію.

У таблиці FE-файли — `src/views/` або `src/components/`, BE-файли — `app/Services/`, якщо не уточнено. Докази `S8` — [попереднє приймання](../f8-live-acceptance.md), `BE` — існуючі backend-тести; їхній hosted результат для точного старого SHA наведено в [Stage 9](../defense/testing-and-results.md). Нові локальні результати — [операційна перевірка](operational-verification.md).

## Неузгодженості та запропоновані рішення

- **C1, deletion проти історії.** S2:L294 каже «видаляти», реалізація зберігає Reminder як cancelled, уже доставлений Inbox не відкликає. Пропозиція: погодити функціональне скасування як основну UX-операцію, зберегти історію; до погодження R32 лишається partial. Буквальний DELETE потребуватиме policy/FK/retention рішення, не frontend-кнопки.
- **C2, автоматичне перенесення.** S1 просить механізми перенесення, S2 — автоматично знайти час, S3 називає автоматичне перенесення. Це не однозначна вимога автономного background trigger. Пропозиція: мінімальний scope — explicit preview/confirm + new plan для missed роботи; якщо потрібна повна автономність, A3. Не оголошувати її наявною за будь-якого рішення.
- **C3, «керувати вільним часом».** Пошук/використання слотів реалізовано; AI редагування availability — ні. Пропозиція: уточнити, чи означає це редагування обмежень; у разі так потрібна окрема proposal capability.
- **C4, звіт.** S1/S2 не визначають завантажуваний формат; in-app period report закриває буквальний запит. Пропозиція — лишити file export кандидатом розвитку. Не називати PDF/XLSX реалізованим.
- **C5, алгоритм у прикладі S3.** Там агент «розподіляє роботу»; архітектура й Stage 10 явно залишають deterministic planning серверним Services. Агент обирає та послідовно викликає Tools; це зберігає намір автоматичного плану без другого алгоритму в LLM.
