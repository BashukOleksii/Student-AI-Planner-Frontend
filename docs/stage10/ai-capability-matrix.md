# Фактичні можливості AI-агента

[Зміст](README.md) · [Вимоги](requirements-coverage.md) · [Операційні перевірки](operational-verification.md)

## Джерело істини та результат

Перевірено `AgentOrchestrator`, `Tools/ToolRegistry`, `ToolExecutor`, `ReadOnlyTools`, `ManagementReadTools`, `OpenAiResponsesProvider`, три action registries, validators/presenters і `TaskActionConfirmationService` з planning/management delegation. Фактична сукупна allowlist — **23 унікальні definitions: 9 reads + 14 proposals**. Сам `ToolRegistry` має 7 reads; ще 2 додає `SubtaskReminderActionRegistry::readDefinitions`. Це важливо для точного підрахунку.

Поточна детермінована перевірка backend: **2084 Unit cases, 6273 assertions, exit 0**, без Laravel application boot/БД/платного provider. FE AI tests входять у фінальну локальну регресію. Історичні Feature tests справжніх Services/persistence/ownership/confirmation підтверджені backend CI для незміненого HEAD; вони не replay-илися на retained S8 DB.

Тести з fake/mock `LlmProvider` **задають** обраний Tool і перевіряють allowlist, arguments, порядок, delegation, safe results та protocol. Вони не доводять, що реальна LLM правильно зрозуміє довільне речення. Real NL selection / provider quality — **BLOCKED** окремим authorization gate. Unsupported capability не симулюється.

## Репрезентативні природномовні сценарії та фактична перевірка

Фрази нижче — демонстраційні запити й очікуваний структурний шлях, не журнал виконаних paid requests. Для мутацій Unit перевіряють schema/state/dispatch boundaries; історичні Feature — реальні writer transactions, replay, policy та receipts. Frontend deterministic tests перевіряють видимі наслідки тих самих структурованих результатів.

| Запит                                 | Дозволений шлях / валідація                                                                                              | Результат / перевірка                                                                                                              | Межі                                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| «Які заняття завтра?»                 | trusted clock/timezone → get_schedule_for_date(date)                                                                     | AgentOrchestratorTest clock/owner/correlated output; AiToolFoundationTest rejects bad dates/owner arguments                        | Реальне тлумачення слова «завтра» provider не перевірялося                           |

## Безпека, виконання та відновлення

- Authenticated User походить лише із Laravel auth; validators не приймають довільні owner/class/service targets. `ToolExecutor` відхиляє unknown_tool та invalid_arguments до adapter; помилки мають safe codes без SQL/provider payload. Unit AiToolFoundationTest перевіряє це без БД; cross-owner persistence — історичні Security/AI Feature tests.
- `AgentOrchestrator` перевіряє весь batch до execution, унікальні call IDs між rounds/history, limits часу/розміру/кількості, послідовно додає correlated Tool results до наступного provider call. Global proposal count включає invalid/cross-domain attempts. Unit AgentOrchestratorTest, TaskActionTest, SubtaskReminderActionTest, PlanningActionTest пройшли зараз.
- `OpenAiResponsesProvider` перевіряє конфігурацію, забороняє виклик усередині DB transaction, не переходить redirect, не робить retry, перевіряє bounded Responses output/continuation, credential echo; зберігає encrypted continuation без raw reasoning. Існуючий OpenAiResponsesProviderTest використовує HTTP fake; його попередній CI результат не означає реального paid smoke.
- Proposal snapshots/fingerprints фіксують огляд/ціль; confirm повторно перевіряє ownership, актуальність, token/expiry/feasibility. Executed action replay повертає immutable receipt без другого writer. Rejected/expired не виконуються; failed planning має безпечний event, savepoint rollback. Unit state/token tests зараз PASS, transaction/idempotency Feature evidence — попередній backend CI.
- FE `useAiConversation` перед confirm читає поточну дію, порівнює огляд, зберігає окремі unchecked partial/unplaced-cancellation consent, після uncertain response читає state/receipt без blind mutation replay. `AiActionReview` показує unsupported types як непідтримані; `refreshAiDomains` читає змінені домени. Відмова/expiry/failure не показуються як успішна зміна.

## Непідтримувані запити

AI **не може** створювати/редагувати/скасовувати Lessons чи replacements; імпортувати XLSX; змінювати catalogs/profile/password/preferences/availability; видаляти Tasks/Subtasks або міняти порядок дітей; complete/miss/cancel StudySession; запускати dispatcher, керувати Inbox, надсилати email/SMS/push; експортувати календар/файл звіту або працювати з командною доступністю. REST-можливості деяких цих операцій існують у ручному UI, але Tool allowlist їх не відкриває.

Звичайна текстова відповідь provider про виконану непідтримувану дію не доводить mutation. Наявний protocol примусово замінює provider mutation wording для prepared proposals на server-controlled confirmation-required текст. Реальний smoke залишається **BLOCKED**: немає окремого bounded платного дозволу та private credentials; frontend provider keys не додаються.
