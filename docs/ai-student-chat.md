# Студентський AI-чат: повідомлення й безпечний огляд

Зміни лише у Frontend, у `main`. Перед початком корінь перевірено через `git rev-parse --show-toplevel`, `git status --short` був порожній, прочитано `AGENTS.md`. Контракт звірено з локальним Backend `226e3ce`, `docs/ai-ukrainian-messages.md`. Backend не редагувався. Живий LLM не використовувався.

## Відображення

- `src/types/ai.ts` і `src/api/ai.ts` читають чинне необов’язкове `server_message` з POST та GET. Невідомі або неповні ознаки ігноруються, решта повідомлення залишається доступною.
- `aiTimeline.ts` поєднує POST та історію за ID повідомлень, у межах ходу зіставляє результати за `call_id`. Дані інструментів не видаляються зі стану. Приховування не залежить від латиниці, сусідства з карткою чи самого факту виклику інструментів.
- `proposal_ready` приховує тільки підсумок для картки з тим самим `action_id`, яка зараз відображається в цій розмові. Коли картка не завантажена або вибрана інша дія, залишається український підсумок. Це ознака походження, а не статус виконання.
- `proposal_not_created` відображає одну структуровану причину відмови `propose_semester_occurrence_create` замість загального підсумку. Без доступної причини залишається одна загальна українська підказка. Причина не переноситься до наступного ходу; POST, replay та GET не створюють додаткових бульбашок.
- Змістовні відповіді й уточнення зберігаються, включно з текстом поруч із tool calls. Назви предметів, імена та довільний текст студента не перекладаються.
- Старі англійські шаблони локалізуються лише за точним каталогом Backend. Приховування старого підсумку потребує підтвердженого зв’язку `assistant_message_id` → POST action → показана картка. Для старого GET без цього зв’язку підсумок залишається. Старі записи не переписуються.
- `action_event` визначає повідомлення про рішення. Якщо той самий стан уже показано у вибраній картці, дубльована подія у стрічці не відображається. Події інших дій залишаються доступними. Застаріла спроба прибирається зі стрічки лише коли вибрана картка вже повідомляє, що потрібна нова пропозиція.

## Картки та підтвердження

З `AiActionReview` і вкладених оглядів завдань, планів, занять, доступності й семестру вилучено технічні секції, включно зі згорнутими. Огляди та квитанції більше не обходяться рекурсивно для відображення. ID, коди й машинні статуси залишаються даними для перевірки/посилань, але не студентськими підписами.

Видимими залишаються предметні поля, дати, час, результат і зрозумілі наслідки. Текстові effects беруться з точного каталогу відомих описів Backend; довільні effects не показуються. Незнайомі наслідки, невідомі типи та пошкоджені підтримувані огляди блокують підтвердження, залишаючи відхилення. Це перевірка читабельності контракту, а не розрахунок плану чи реалізація серверних бізнес-правил.

Кількість майбутніх сесій береться лише з `completion_review.future_sessions_count`; кількість залежних нагадувань сесії — з перевіреного `dependent_reminders.scheduled_count`. Відсутній лічильник не вгадується з тексту. Відомий динамічний текст завершення не виводиться повторно поруч із лічильником.

Окремі згоди на частковий план, скасування без заміни та поділ збережено. Картка нової пари й перевірка її фактично збереженого результату використовують попередню доменну валідацію.

`AiNotice` відображає тільки фіксовані українські пояснення за відомими кодами/HTTP-статусами. Сирий текст помилки, поля з довільними повідомленнями та коди не виводяться. Втрата відповіді не означає виконання чи відкату: чинний механізм робить безпечний GET і пропонує перевірку стану. Автоматичного повтору confirm/reject немає.

## Перевірки

Точні команди з кореня Frontend:

```bash
npm run type-check
npm run build
npx vitest run tests/ai-api.test.ts tests/ai-ui.test.ts tests/ai-state.test.ts tests/ai-semester-occurrence.test.ts tests/ai-session-lifecycle.test.ts tests/ai-lesson.test.ts tests/ai-lesson-state.test.ts tests/ai-availability.test.ts tests/ai-availability-state.test.ts tests/ai-student-chat.test.ts tests/page-content.test.ts
npx playwright test e2e/ai.spec.ts e2e/ai-semester-occurrence.spec.ts e2e/ai-student-chat.spec.ts e2e/ai-lessons.spec.ts e2e/ai-availability.spec.ts --workers=2
```

Результати фінальних перевірок:

- `npm run type-check` — успішно, exit 0.
- `npm run build` — успішно, exit 0.
- Наведений вище Vitest-прогін — **11 файлів, 365/365 тестів успішно**, exit 0.
- Наведений вище Playwright-прогін — **60/60 сценаріїв успішно**, desktop і mobile Chromium, exit 0 (1,3 хв).
- Prettier для всіх змінених файлів та `git diff --check` — успішно.

Playwright використовує підробний API, desktop/mobile Chromium, перевіряє вузькі екрани, явне підтвердження, відновлення невідомого результату, картку пари й окремі згоди плану. Наявні сценарії також перевіряють клавіатуру, теми та axe. Це не інтеграційний тест живого Backend або LLM. Повний репозиторний набір, Firefox/Safari та мовна поведінка живої моделі не перевірялися.
