### Proposal→explicit decision→receipt mapping

Усі 21 готують **тільки proposal** через `POST /api/ai/conversations/{conversation}/messages`. Action list/detail GET незмінні. Єдиний decision path:

- `POST /api/ai/conversations/{conversation}/actions/{action}/confirm`;
- `POST /api/ai/conversations/{conversation}/actions/{action}/reject`.

Кожна non-planning confirmation та кожне rejection передає `{}`. Planning confirm може передати тільки свої documented consent flags; domain arguments/target IDs/timezone/fingerprints/review tokens не надсилаються клієнтом. Нижче всі writers виконуються **лише** через чинний authenticated AiActionDecisionService після explicit Confirm.

Перелік UI компонентів вище — чинні `src/components/ai/`; спільні controls лишаються в AiActionReview. API/parser валідовує action identity, `reviewSupported()` — відомий material contract. Lesson/availability мають domain runtime narrowing; unsupported/malformed material не confirmable, safe reject доступний за чинним workflow. Unknown future types fail closed.

Спільні safety mechanisms: fresh detail GET перед confirm, semantic comparison із показаним material, UUID identity, duplicate-submit disable, AbortSignal/navigation cleanup, CSRF/authorization, server expiry, terminal history/replay information, changed material→новий review без auto-confirm. «Так» у chat — нове message, а не виклик decision endpoint. `action_stale`/validation/conflict/expired/rejected не відображаються applied; response loss→GET authoritative action, без повторного mutation POST. Лише executed action з валідним durable receipt доводить виконання. Replayed означає попередній write, не другий.

Після execution `refreshAiDomains()` виконує відповідні authoritative reads. Refresh failure відокремлений від mutation success і не стирає receipt. Lesson refresh охоплює original/moved date boundaries; availability — `planningApi.availability()`, без arbitrary free-slots requests. Route views refetch on navigation, global cache інфраструктури немає; protected local previews dispose. Stale availability review nonconfirmable: current windows можна перечитати, потрібен новий AI proposal, без retarget/merge.

Recurring availability: ISO weekday зберігається, exact `09:00:00` і `24:00:00` не проходять через Date/UTC conversion. Preview/receipt мають historical persisted timezone, не новий profile timezone. Delete receipt зберігає removed record. Усі вісім effect flags перевіряються: змінюється recurring configuration, delete додатково removes window; Task/Lesson/StudySession deletion, Reminder/numeric preferences changes та auto-rescheduling відсутні. Replanning — інший explicit workflow.

**REST-only:** academic catalog CRUD, profile/passwords, XLSX import, Task miss/delete, child delete/reorder, session complete/miss/cancel, Inbox read, numeric planning preferences, Lesson delete/restoration. **Unsupported AI operations:** team/calendar, arbitrary bulk/delete/import, catalog name lookup (G19-05), dedicated workload-advice Tool. Це не означає відсутність REST workload page або AI factual statistics. Provider fakes доводять guards/protocol, але не здатність real LLM правильно інтерпретувати будь-який український запит (V19-03).

Це browser test navigation synchronization defect, не доведена помилка API/доставки й не environmental browser-install blocker. Isolated test PASS узгоджується з timing-dependent причиною; два full FAIL не приховані.
