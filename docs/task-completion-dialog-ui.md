# Завершення роботи зі сторінки завдань

Зміни виконано у локальному Frontend на `main`, після читання `AGENTS.md` та перевірки `git status --short`. Наявні зміни перепланування залишено в робочому дереві.

## Перевірений контракт

Локальний Backend знайдено у `../student-planner-backend`; корінь підтверджено через `git rev-parse --show-toplevel`. Перевірено контролери, ресурси відповідей, `StudySessionRangeRequest`, `StudySessionReadService`, `StudySessionLifecycleRules`, `StudySessionLifecycleService`, `WorkCompletionService`, сервіси завдань/підзавдань і `TaskDependencyCleanupService`. Backend не редагувався.

- `GET /api/study-sessions` вимагає `start_date` та `end_date`, приймає до 31 календарного дня й повертає `{data: StudySession[], meta: {start_date, end_date, timezone}}`. Поля `page`/cursor не підтримуються, зайві поля відхиляються. Тому використано наявний пошук періоду під «Не бачиш потрібної сесії?», без кнопки удаваної серверної пагінації. Початковий пошук — за останні 31 день у часовому поясі профілю.
- Огляди завершення завдання/підзавдання повертають без обгортки `future_sessions_count`, `completion_token`, `message`. Лічильник охоплює всі відповідні майбутні заплановані сесії, незалежно від періоду пошуку в діалозі.
- Завершення тільки роботи виконує один `POST /api/tasks/{id}/complete` або `/api/tasks/{id}/subtasks/{id}/complete` з токеном огляду. Сервер скасовує майбутні заплановані сесії, не зараховуючи минулі як виконані.
- Огляд конкретної сесії повертає `can_complete_work`, `work_type`, `completion_review`. Для спільної дії використано чинний один `POST /api/study-sessions/{id}/complete` з `actual_minutes`, `complete_work: true`, `completion_token`. Серверна транзакція завершує роботу, сесію та скасовує відповідні майбутні сесії атомарно.
- Спільне завершення доступне для пов'язаної сесії зі статусом `planned`, яка вже почалася; фактичні хвилини обов'язкові. Остаточну перевірку виконує Backend. Для сесії підзавдання завершується саме підзавдання.
- Видалення скасовує відповідні майбутні заплановані сесії та заплановані нагадування. Минулі сесії не перетворюються на завершені.

Форми відповідей звірено з поточним кодом локального Laravel. Живі авторизовані HTTP-записи не виконувалися; інтеграційні та браузерні тести використовують локальні моки цих відповідей.

## UI та поведінка

Діалог має дві компактні картки з незалежними формами. Перша завершує тільки роботу навіть за наявності вибраної сесії, помилки або порожнього пошуку. Попередження про скасування з'являється лише за позитивного серверного лічильника. Чинне явне підтвердження наслідків збережено.

Друга картка містить розпочаті пов'язані заплановані сесії: дату, час і заплановану тривалість. Жодна не вибирається автоматично. Поле фактичних хвилин з'являється після вибору та залишається порожнім. Для підзавдання показано його назву та пояснено, що стан основного завдання не зміниться. Пошук дат розкривається окремо; помилки дат показано всередині пошуку. Порожній результат: «За цей період немає сесій, доступних для завершення».

Перед записом збережено перевірки актуальності роботи й сесії. Контекст обраної дії фіксується на початку запиту. Помилка або непідтверджений статус не закривають діалог як успіх; невизначений запис не повторюється автоматично.

Статуси відображаються як «Очікує виконання», «Не виконано» та «Завершено». Прострочення залишається окремою позначкою. Дедлайн не змінює серверний статус у Vue. Тексти видалення уточнено: скасовуються майбутні заплановані сесії й час звільняється.

## Файли цього етапу

- `src/components/domain/WorkCompletionDialog.vue` — дві картки, незалежні дії, пошук під розкриттям, короткі рядки сесій і точний підпис підзавдання.
- `src/composables/useWorkCompletion.ts` — незалежна доступність дій, окремі помилки пошуку, фіксація контексту операції.
- `src/views/TasksView.vue`, `src/components/domain/TaskSubtasks.vue` — уточнення наслідків видалення.
- `src/utils/tasks.ts` — підпис статусу `completed`: «Завершено».
- `tests/task-work-completion.test.ts` — перевірки незалежних дій, серверного лічильника, фактичних хвилин, підзавдання, давнішого періоду, порожнього/помилкового пошуку та помилок запису.
- `tests/task-actions-status.test.ts` — відмінність статусу від прострочення, текст видалення.
- `tests/helpers/workCompletionBackend.ts` — мок пошуку тепер фільтрує за періодом відповідно до реального API.
- `tests/ui.test.ts`, `tests/subtasks.test.ts` — актуальні підписи завершеного статусу; очікування завершення асинхронного переходу після 401.
- `e2e/task-work-completion.spec.ts` — дві картки, пошук давнішої сесії підзавдання, спільна атомарна дія, мобільний вигляд.
- `docs/task-completion-dialog-ui.md` — цей звіт.
