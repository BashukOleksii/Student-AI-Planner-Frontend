## Стрічка та причини

`AiTimeline` показує повідомлення студента, змістовний текст агента, структуровані результати дій і одну причину невдалої пропозиції. Порожні виклики інструментів, службові результати читань, «Дані перевірено», назви інструментів, call IDs, сирі коди та JSON не відображаються. Текст змістовного повідомлення з `tool_calls` збережено. Статуси підтвердження, відхилення, прострочення й потреби нового огляду залишилися доступними. Службовий текст запису `action_event` замінено його структурованим людським статусом.

Службові поля не видалено зі стану/адаптера. Додано необов'язковий `error_reason` для `data.tools[]` після POST і `tool_result` після GET. Для невдалого `propose_semester_occurrence_create` підтримано:

- `pair_number_taken` — «Цей номер пари вже зайнятий»;
- `time_overlap` — «Обраний час перетинається з іншим заняттям»;
- `date_cancelled` — «Цей день скасовано. Спочатку віднови або явно заміни його розклад».

Без причини або за невідомого значення показано одну безпечну загальну підказку. Текст моделі не використовується для визначення причини, зв'язування або усунення повторів.

Підтверджені відповіді POST зберігаються лише в пам'яті відкритої розмови. `user_message_id`, `assistant_message_id` та `call_id` зв'язують їх з історією. Вони доповнюють недоступну сторінку історії без оптимістичних повідомлень. Історичні результати групуються в межах ходу за ID повідомлень студента; повторний call ID в іншому ході не переносить причину туди. Одна підказка залишається в первинному ході після наступного читання та оновлення історії.

## Картка та підтвердження

Тип `propose_semester_occurrence_create` додано до чинного списку підтримуваних дій і перевірок огляду. Компактна відповідь POST розпізнає тип із `preview.type`, повний ресурс — із `type`. Явне підтвердження працює через чинний endpoint і повторну перевірку поточного ресурсу; нових API-записів не додано.

Перед дозволом підтвердження перевіряються одна дата, незмінність відображуваних даних усіх наявних пар, унікальність номерів і рівно один новий номер. Порівнюються предмет/викладач, їхні назви, час, аудиторія, тип і позначення пари. Проєктовані occurrence/snapshot IDs не є ідентичністю для цього порівняння. Враховано перехід базового дня у snapshot, перестановку рядків та суботу з раніше доданою парою. Неповний, суперечливий або неоднозначний огляд не дозволяє підтвердження; відхилення залишається доступним.

Картка показує лише нову пару: дату з роком, номер, предмет, викладача, час у зоні огляду й аудиторію за наявності. Є пояснення «Зміна лише на цю дату. Інші пари залишаться без змін». Картку розташовано одразу під відповідями агента, перед полем нового повідомлення. Повний список дня та проєктовані посилання на заняття не показуються.

Після успіху відображається одна картка зі збереженого `receipt.after`, перевірена за ідентичністю дії та семантикою огляду. Після повторного відкриття виконана дія не має активного confirm. Для неперевіреного збереженого результату запропоновано перевірити стан, а не повторити додавання. Чинне відновлення після мережевої невизначеності використовує безпечні GET і явну перевірку стану, без автоматичного повтору запису.
