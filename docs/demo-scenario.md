# Academic demonstration scenario

Use the real Vue application and Laravel REST API with an explicitly authorized demo account and nonvaluable data. This is an operator runbook, not evidence that these demonstrations have run. See [F8 acceptance](f8-final-acceptance.md) for actual results and outstanding gates. Keep credentials, cookies and grants outside Git.

## Preparation

Record both repository commits, actual origins, effective database identity, account ID, profile timezone and permissions. Run `php e2e/support/inspect-backend.php /path/to/backend` for read-only metadata. Confirm the running HTTP server uses that checkout/configuration; CLI output alone cannot attest the HTTP process. Do not migrate, reset, purge or select another account as a recovery shortcut.

Keep a private fixture ledger with a unique demo label and every created Institution, Period, Subject, Teacher, Lesson, import Batch, Task, Subtask, Session, Reminder and Notification ID. Record IDs immediately after creation, including on interrupted runs. Retain history after the demonstration. Inspect persisted state before retrying uncertain import/planning changes.

Use `public/examples/schedule-example.xlsx`, available through the application's download link. It matches the backend's supported workbook. Choose a period covering the intended weekdays and use the exact Subject/Teacher names shown by the persisted preview. Arbitrary spreadsheets are not a reliable fallback.

Prepare pending estimated work with future deadlines and real availability/capacity. Demonstrate partial allocation or cancellation consent only if Laravel actually produces that condition. For full allocation, show that genuine result and identify partial-consent automated evidence separately.

Prepare historical activity ahead of time through authorized application operations. Allow Sessions to finish before completing/missing them; do not change clocks or backdate database rows. Include two completed Sessions, one with known actual minutes (for example 25), one left unknown, and a missed Session. Complete a separate Task and a child of a different still-pending Task. Record actual starts, completion timestamps, durations and deadlines. Select local report dates containing that activity. If those are the only eligible records, expect two completed Sessions, 25 known minutes, one known-duration completion, one unknown-duration completion and one independent Task/child completion each. Match scheduled seconds to the ledger. An empty previous period supports delta checks but does not prove nonzero historical calculation.

Actual dispatch requires separate permission for the entire isolated disposable database. Record the existing dispatch command's output, sent Reminder and exactly one Notification across all Inbox pages. Provider use requires separate paid-call authorization, billing/credentials and an owned conversation; AI side effects require their own permission.

## Defense explanation and fallback

Vue owns interaction, accessible forms/reviews, transport and presentation. Laravel Policies enforce ownership. Services own deterministic planning, scheduling conflicts, lifecycle synchronization, import transactions, delivery and statistics. Registered AI Tools reuse those Services. The model orchestrates calls and proposes actions; it does not become the planning algorithm or bypass confirmation. Durable AI receipts and direct transient preview tokens have different recovery semantics.

Keep the [acceptance matrix](f8-final-acceptance.md#acceptance-matrix) available. If Laravel is unavailable, show the real failure/retry UI and explain the dependency. Screenshots and deterministic tests are supporting evidence with explicit labels. If scheduler/provider access is unavailable, continue independent modules. Never hardcode demo records, add demo endpoints, reset databases or make unapproved paid calls to rescue the presentation.
