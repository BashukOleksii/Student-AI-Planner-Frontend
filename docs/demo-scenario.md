# Операторський сценарій демонстрації

Матеріал для підготовки реального показу, а не звіт про вже виконані дії. [Промова на 14 хвилин](defense/defense-script.md), [план слайдів](defense/presentation-outline.md), [докази Stage 8](f8-live-acceptance.md#stage-8--final-live-system-acceptance), [архітектура](defense/architecture.md).

## Що вже доведено

Ядро Stage 8 — **CONDITIONALLY ACCEPTED**: один реальний системний сценарій пройшов через Vue → Laravel → MySQL; authenticated reads, 66 незалежних GET і SQL-зіставлення підтвердили збережені ефекти. Реальний paid-provider і диспетчер не запускалися. Не називати сьогоднішній перегляд записів повторним виконанням усіх цих тестів.

## Підготовка до майбутнього показу

Підтвердити фактичні commits, isolated runtime/root, SQL database/account, доступність фронтенду/API, timezone та чинний сеанс дозволеного користувача. Використовувати вже підготовлену `studentplanneracceptance`; не змінювати `student_planner` або `student_planner_testing`. Старий grant має строк дії й не дає безстрокового дозволу на нову демонстрацію. Нові persistent fixtures для виступу потребують актуальної операторської авторизації. Stage 9 не створює їх і не запускає тести.

Перед виходом на публічний екран увійти дозволеним користувачем у приватному режимі оператора. Не показувати email/пароль, cookie, request headers, `.env`, `.auth/`, приватний ledger чи повні журнали. Для демонстрації автентифікації використати оновлення захищеної сторінки й схему Sanctum; введення credentials виконати поза трансляцією. Якщо потрібен профіль, приховати персональні поля, показавши лише дозволений timezone.

Залишити час на перевірку обраних майбутніх дат. Збережені Stage 8 Sessions стосуються 16–22.11.2026; на іншій даті захисту їхні lifecycle-умови можуть бути іншими. Не змінювати годинник і не backdate-ити записи.

## Збережені дані для читання

| Модуль                      | Наявний доказ                                                                 | Як показати без повторення мутацій                                                                               |
| --------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Academic Context / Schedule | Institution/Period 1, Subjects/Teachers 1–8; 15 imported Lessons і blocker 16 | Відкрити власні довідники й тиждень 16–22.11.2026                                                                |
| XLSX                        | Batch 1 committed, 15 рядків; Batch 2 committed із 15 duplicate/noop          | Відкрити `/schedule/imports/1` і `/schedule/imports/2`; пояснити підтверджену історію, не імітувати новий upload |
| Task/Subtask                | Task 1 completed, child 1 pending                                             | Пояснити незалежність статусів і progress 0/1                                                                    |
| Preferences / Availability  | 45 хв/день, 90 хв/тиждень, 5 хв перерва, 15–30 хв сесія, 7 вікон 20:00–22:00  | Показати фактичні значення без перезапису                                                                        |
| Planning / Sessions         | Original Sessions 1–4: 5400 секунд; chain 1 → 5 → 6                           | Відкрити історію, окремо показати original/replacement/cancelled                                                 |
| Reminders                   | 1–4 cancelled після перевірених змін цілей                                    | Пояснити absolute/relative й збережені trigger, не називати cancelled нагадування доставленим                    |
| Statistics                  | Task completion 02.11.2026, on_time=1; child pending; delta +1                | Обрати 27.10–02.11.2026 і baseline 20–26.10.2026; не покладатися на «сьогодні» іншого дня                        |

Ці ідентифікатори — навігація оператора, не персональні дані для слайдів. Для публічного показу використовувати лише попередньо погоджені навчальні назви/поля. У цьому акаунті вже є записи: **не запускати `test:live:system` повторно**, бо сценарій вимагає порожнього профілю. Не очищати БД заради демонстрації.

## Нові дії лише за чинного дозволу

Якщо дозволено підготувати новий демонстраційний ланцюг, створити одну нову Task і одну Subtask у тому самому дозволеному профілі. Використати наявну власну дисципліну, майбутній дедлайн і явно задані estimated_minutes. Для нового плану обрати саме цю pending-роботу, а не завершений Task 1. Із семи поточних вікон і ліміту 90 хв/тиждень може вийти частковий результат для роботи на 180 хв; показувати тільки фактичну відповідь сервера.

Заздалегідь вибрати майбутній тиждень із реальною місткістю. Збережені planned Sessions 2–4 можуть блокувати попередній тиждень. Вільні слоти не гарантують повний план: враховуються дедлайни, навантаження, тривалість і перерви. Не змінювати ліміти непомітно, щоб отримати бажаний кадр.

Для реального upload користуватися [підтриманим файлом](../public/examples/schedule-example.xlsx), існуючим AcademicPeriod і точними довідниками. У заповненому середовищі повторний файл закономірно дасть duplicate/noop. Такий результат демонструє справжній парсинг і безпечний reimport, але не створення ще 15 Lessons. Preview/Batch уже є persistent записами; перед commit оглянути наслідки.

Після підтвердження нового плану заздалегідь дозволений manual Lesson може створити реальний blocker у вибраній сесії. Тільки тоді запитати replanning preview, оглянути причини й явні згоди, підтвердити та відкрити original/replacement. Якщо цей live-показ не підготовлений, використати наявний chain Stage 8 як перегляд доведеного результату.

Для Reminder задати майбутній absolute trigger або відносний offset до дозволеної pending-цілі. Створення запланованого Reminder не є доставкою. Dispatcher, paid AI й deployment не входять до цього показу без власної окремої авторизації.

## Безпечне відновлення під час виступу

| Проблема                                 | Дія і пояснення комісії                                                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 401 / 419                                | Приховати екран із приватними даними, відновити сеанс свідомо; не повторювати невизначену мутацію автоматично            |
| Втрачена відповідь upload/commit         | Прочитати відомий Batch; committed означає збережений результат. За невідомого ID не створювати повтор наосліп           |
| 409 імпорту або плану                    | Показати актуальний огляд і причину нового підтвердження; не обходити перевірку                                          |
| Втрачена відповідь планування            | GET Sessions/цільового діапазону перед будь-яким новим confirm                                                           |
| Немає capacity                           | Показати справжній unscheduled/empty результат; пояснити обмеження й перейти до збереженого прикладу                     |
| Session ще не eligible для complete/miss | Пояснити часову умову; показати читання історії або future cancel/reschedule, якщо вони дозволені                        |
| Немає AI-провайдера                      | Показати схему Tools і реальний детермінований REST-preview; це запасний спосіб пояснення, не запис платної AI-відповіді |
| Порожній Inbox                           | Пояснити відсутність запущеної доставки. Не створювати browser-based сповіщення                                          |
| Backend недоступний                      | Показати чесний error/retry UI та опублікований звіт; скриншот позначити як записаний матеріал, не live API              |

Нові успішні ID та невизначені дії фіксує оператор у приватному ledger. Не видаляти історію й чужі дані після показу; невдалий сценарій не є приводом для reset. Довговічне AI action/receipt recovery відрізняється від прямого transient planning token.

## Порядок показу

Вступ → архітектура → автентифікація → академічний контекст і розклад → XLSX → Task/Subtask → вільний час → preview/confirm → Sessions/replanning → Reminders → Statistics → AI Tools та чесний fallback → тести, межі й висновок. Розклад часу, промова та скорочений варіант наведені у [сценарії захисту](defense/defense-script.md).
