## Defects and corrections

1. **Frontend integration tooling: inaccessible development overlay.** The first complete live workflow reached AI and then failed axe with `aria-prohibited-attr`: Vue DevTools injected a `div` carrying `aria-label` without an accessible role. The default production/offline browser suite does not include this development overlay. The smallest correction adds Vite's `integration` mode, which omits only the developer overlay. The runner starts real Vite in that mode. The same live axe assertion remains enabled and passes; ordinary development retains DevTools. No application accessibility check was disabled.
2. **Integration evidence collision.** Running ordinary Playwright with its default output root removed the nested live evidence directory, causing three `ENOENT` test-report failures and an interrupted scheduler observation. The new live harness now writes to independently ignored `fullstack-results/`. Real database writes were unaffected. A later run completed the workflow while ordinary offline Playwright ran independently; its evidence survived. The regression is exercised by those concurrent verification commands.
3. **Test-only reset-mail decoding.** Blind quoted-printable decoding interpreted the first two digits of a plaintext hexadecimal token as an escape, making reset-link capture intermittent. A recipient-scoped parser now preserves raw tokens and decodes explicit encoded equals/soft breaks. Five Vitest regressions cover numeric/letter prefixes, HTML, recipient selection and quoted-printable input. Password business code was not changed.

Other intermediate failures were harness fixture/contract errors: Monday-only parity anchor, Chromium datetime/time input format, required session date bounds, ID-only session labels, existing route/button labels, valid alphabetic teacher names, refresh create/replay HTTP statuses, and replacing an incorrectly resolved mutex interface with the event's real mutex. Recovery legitimately placed a replacement earlier than the original session, so the readback range was corrected to include today. CORS with one configured allowed origin can return that fixed origin for an untrusted request; the security assertion now checks that it never authorizes the untrusted origin. These were not demonstrated domain/authentication defects and no business rules were changed.

Backend changes are confined to the disposable full-stack runner, guarded test HTTP/CLI entries, controlled model provider, two DB-free guard regressions and testing documentation. Frontend changes are the integration Vite mode, isolated Playwright configuration, real-stack scenarios, safe mail parser/tests, a convenience npm command, output ignore rule and documentation. No migration, API route, Controller, model, Service, production provider/auth setting or database schema was changed.
